### 2.1 The integrity guarantee

```sql
CREATE UNIQUE INDEX report_versions_one_current_per_report
    ON public.report_versions (report_id) WHERE is_current;
```

Enforced **at the database level**, so two concurrent "new version" operations can no longer both become current. The migration refuses to run over invalid data (a `DO` block raises if any `report_id` already has more than one current version) and asserts its own postcondition. **No lifecycle semantics, column, grant, policy or RLS flag was changed, and no data was touched.**

### 2.2 Posture documented where it cannot be lost

The ratified **fail-closed, app-layer-only** posture is recorded as `COMMENT ON TABLE` for **both** tables (original comment text preserved, posture appended) and as a comment on the new index — so the reason "RLS enabled + zero policies" is intentional travels with the schema itself.

The **schema is intact** — every migration, including this task's index, was verified present afterwards.
* **No production, demo or authoritative database was affected:** the protected names are not present on this local server, the guard never triggered, and no production connection was ever opened. This is **not** data loss for any authoritative dataset, and it matches the harness's designed behaviour (it resets a *dedicated* test database).
* **Operational convention adopted from here:** run integration suites against a **disposable clone** (`ct_*_20260913` style), **never** against a persistent environment whose rows matter; treat any row-count observation as meaningful only *before* such a run.
