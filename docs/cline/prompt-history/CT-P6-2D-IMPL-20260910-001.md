3. **Firm resolution** via a new public resolver built on the existing `_resolve_context`; no request input reaches the recorder.
4. **Mode source** = the existing authoritative predicate at the boundary (actor-agnostic); no actor/mode coupling, no consultant-specific mode semantics.
5. **FK `ON DELETE SET NULL`** so provenance can never block an existing firm-deletion flow.
6. **Call sites placed immediately before each mutation**, so provenance is recorded for actions that actually occur (requests denied before mutation record nothing).
7. **No migration applied to any database** (conservative; recorded as deployment prerequisite U1).
