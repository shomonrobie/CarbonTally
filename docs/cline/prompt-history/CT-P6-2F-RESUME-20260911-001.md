**2.2 F4 — the three skips (root cause proved).** A standalone Playwright probe (real
`consultant_a` login) measured each guard at both moments: at the guard the page body was
literally `"Checking access…"` and the probe returned `false`/`0`; after waiting for the
route data it returned `true`/`true`/`2`, with the workspace API reporting
`"calculated"` for the item under test. The specs therefore probed with non-waiting
`isVisible()`/`count()` against the SPA's access gate. **Harness defect, not product
defect.** Fixed by adding `waitForAccessCheck()` and `visibleAfterLoad()` to
`tests/e2e/personas.ts` and using them before the guards (the DENY specs were
deliberately left alone, because for them absence of the workspace *is* the assertion).
Result `3 skipped / 13 passed` → **16 passed / 0 failed / 0 skipped**.

**2.3 New defect LT-1 (P1) — customer acceptance returned HTTP 500.** Exercising the D11
`accepted` path for the first time surfaced `500 inconsistent types deduced for parameter
$2 / text versus character varying` on
`POST /api/v3/organizations/{org}/consultant-engagements/{id}/accept`; the engagement
stayed `pending` (no transition, no audit, no notification). Root cause:
`backend/data/consultants.py` assigned the same parameter to a `character varying` status
column while comparing it with text literals in `CASE` branches. A rolled-back probe
against the isolated database confirmed the failure and the fix, and showed the same
defect in `update_task_status` (`consultant_tasks`). Fixed with the smallest correct
change — `SET status = $2::text` in both statements, with comments explaining why. The
defect survived because unit tests use a fake repository (SQL never executes) and the
real-DB integration suite is blocked by a stale schema (finding LT-2).

**2.4 D11 evidence completed.** New `e2e/environment/scripts/verify_lifecycle_events.py`
(isolated-only guard; restores the fixtures it consumes) evidenced `accepted`,
`qc_outcome` (approved **and** rejected) and `rework`, each with HTTP outcome, resulting
entity state, the persisted rows' `event_key`/type/recipients/title/link/`actor_domain`,
server-derived firm recipients, replay behaviour (409, no duplicate row) and a denied path
(403). A deterministic pending engagement was added to `seed_lifecycle_fixtures.py` so the
customer acceptance path is reproducible. **30/30 checks passed.**

**2.5 Acceptance and regression.** API acceptance `16/16 PASS`; browser `16/16`; backend
`tests/unit` **1,763 passed / 0 failed / 0 errors / 0 skipped**; `tests/e2e`
