## Approval-Boundary Trace

`calculated → approved` and every equivalent customer-final-approval authority:

**Path A — customer item approval (intended).**
`POST /api/v3/processing/items/{id}/customer-review`
(`v3_processing_workflow.py` ~838-914).
Order of controls: `require_org_admin()` (owner/admin **or** internal staff) →
`_get_checked_item` (item+batch, `ensure_processing_org_access`) → PE-origin guard
(PE work must be `ct_qc_approved`/`customer_review`/`approved`) →
`_require_transition(item, "approved"|"rejected")` → **P6-2B-4 CT-QC prerequisite
guard** → rejection-reason validation → D37 charge (only on approve,
idempotency key `charge:item:{id}`) → `manual_extraction.customer_review(...)`
(stamps `customer_approved/by/at`, sets status) → resolve stale issues.
- Reachable by: **org owner/admin** (and internal staff per `require_org_admin`).
- **Consultant → 403** (not org admin); **PE staff → 403**; **member/viewer → 403**.
- `calculated → approved` is therefore reachable **only** for an item that is
  AUTOMATIC under the P1 predicate (manual → 403 by the P6-2B-4 guard), or from
  `ct_qc_approved` / `customer_review` (CT-QC satisfied).

**Path B — automatic job review (intended, automatic path).**
`POST /api/v3/processing/jobs/{job_id}/review`
(`v3_automatic_processing.py` 466-530). `require_org_admin()` → `_checked_job`
(org isolation) → `job.stage == "review"` (else 409) → `complete_review(...)` →
stamps the source item via `manual_extraction.customer_review(...)` → audit
`automatic_processing:approved|rejected`.
- **No CT-QC requirement** (by design — automatic work is exempt).
- **No D37 charge** (pre-existing; see Findings).
- Member/viewer/consultant/PE → 403.

**Path C — non-approval writers (must not become approval paths).** Entity route
`POST /api/v3/ops/entities/{e}/extraction/items/{id}/status` explicitly rejects
