## Key Findings

### Material correction
* **The "~80–90 audit-ready reports" belief is NOT supported by the repository.** The V3 engine
  supports exactly **one** report type (`annual`, a 12-section structured report;
  `v3_reports.py:63`, `report_generation.py:65`). The larger SECR/CSRD/ISSB/AUDITOR_EXCEL and
  six generic labels are **legacy**, live in a 2,097-line monolith that is **not mounted** by
  `api/router.py`, and are not audit-ready. Recorded as a correction requiring PO acknowledgement (P1).

### Strong reuse findings
* **Analytics already exists**: `EmissionsLogsRepository.aggregate` (scope/month/facility/asset/
  year) + `aggregate_by_activity` / `aggregate_by_supplier`; `ReportingRepository` with 15+
  methods; `/api/v3/emissions/dashboard`, `/scope-breakdown`, `/calculations`; 15 reporting
  endpoints across four actor families.
* **LLM provider abstraction already exists**: `infra/llm_client.py` (OpenAI/Anthropic-compatible,
  stdlib transport, injectable for tests) + `infra/ai_runtime.py` (`CARBONTALLY_AI_BASE_URL` /
  `_API_KEY` / `_MODEL`; truthful `provider_label()` incl. `openrouter`; attribution facts that
  never read the key). Unit-tested. **The "must not be coupled to one provider" requirement is
  already met.**
* **A canonical AI architecture already exists**: `docs/audit/openhands/CARBONTALLY_V3_AI_ASSISTANT_ARCHITECTURE.md`
  (633 lines) — tiered personas, `AssistantGateway`, tool registry, tool contract, injection
  defence, audit model, 7-phase roadmap, 8 open PO decisions. Only Phase 1 (deterministic public
  FAQ widget) is implemented.
* **Evidence architecture exists**: `domain/evidence.py` classifies COMPLETE / PARTIAL /
  UNAVAILABLE from real persisted provenance (no fabricated score).
* **Validation/QC exists**: `ValidationEngine` (~35 `VAL_*` codes), `issues` domain with
  lifecycle + SLA, review + QC queues, extraction confidence.
* **Billing/allowance substrate exists**: `billing_plans.included_credits`, append-only
  `billing_credit_ledger` (idempotent via `external_reference`), versioned `billing_commercial_config`,
  `usage_tracking` — suitable for future AI allowances.

* **Net-zero has no data model at all** (no targets/baselines/trajectories/scenarios); the only

* **No anomaly detection anywhere.**
* **No disclosure-framework engine** (framework names appear only as legacy labels/prose).
* **No estimated-vs-primary data classification**; legacy `confidence_score` population UNVERIFIED.
* **Ask CarbonTally does not exist** (no routes/tables/tools/audit); `AssistantGateway` is design-only.

## Architecture Recommendations

1. **Extend, do not duplicate** — one aggregation layer (`ReportingRepository` +
   `EmissionsLogsRepository`), one report engine, one export surface, one provider abstraction,
   one evidence vocabulary.
2. **Ask CarbonTally**: `User → Ask UI → gateway → controlled tools → authorization/scope/RLS →
   domain/repository → authoritative data → structured result → LLM explanation → answer + evidence`,
   built on the existing canonical design and the existing `infra/` client.
3. **Keep the two conversational domains separate** — human↔human messaging (`conversations`/
   `messages`) vs Ask CarbonTally (own persistence); no messaging changes.
4. **Report authoring**: a separate narrative overlay for customer-editable fields so that
   system-controlled values (calculated figures, factors, evidence, provenance) can never be
   mutated by an edit.
5. **Provider abstraction lives in `infra/`** — extend, never fork.
6. **AI safety is structural**: authorize before data assembly; tools read-only; grounded
   answers; conservative fallback; audit every tool call; the LLM is never the authorization boundary.
