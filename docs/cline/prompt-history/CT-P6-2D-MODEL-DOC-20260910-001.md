The documentation must accurately preserve the original CarbonTally model.

CarbonTally has four principal processing actors:

* **Organisation**
* **Consultant**
* **CarbonTally internal**
* **Processing Entity**

Automatic/manual processing is a **separate dimension**.

The model therefore permits actor/mode combinations where authorized.

Examples include:

* Organisation + automatic processing
* Organisation + manual processing
* Consultant + automatic processing
* Consultant + manual processing
* CarbonTally internal + automatic processing
* CarbonTally internal + manual processing
* Processing Entity + manual processing

* Consultant = manual
* Processing Entity = manual in the generic sense
* Organisation = automatic
* CarbonTally internal = automatic

The reconciliation established that:

> **`CONSULTANT ≠ MANUAL`**

and that automatic/manual is actor-agnostic.

For Processing Entities, preserve the architecture's existing concept that they provide **additional controlled manual-processing capacity**. Do not generalize that into a statement that all "manual processing" belongs to Processing Entities.

# 4. Automatic → manual fallback

Document the existing automatic-to-manual fallback as part of the original system model.

At a conceptual level:

```text
Input
  ↓
Automatic extraction / mapping
  ↓
Confidence / validation gates
  ↓
Success ─────────────→ Continue processing
  │
  └─ Failure / unresolved data
          ↓
     Manual correction /
     extraction / mapping
          ↓
       Continue
```

The documentation must make clear that this is an existing architectural/workflow pattern, not a new Phase-6 feature.

For example:

### CSV / Excel

Automatic mapping may resolve the data.

If data remains unresolved or ambiguous, the authorized workflow can provide manual mapping/correction.

### PDF

Automatic extraction and mapping may succeed.

If extraction/mapping fails or confidence is insufficient, the workflow can move into human correction/manual processing.

Do not invent additional states or capabilities.

Use the existing architecture/code evidence from the reconciliation report.
