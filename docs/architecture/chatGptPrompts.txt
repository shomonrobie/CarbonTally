I think this is the right approach. However, I'd make one improvement.

Instead of writing four unrelated prompts, treat the work as one continuous architecture project. Each phase should explicitly build on the previous one and should not redesign decisions that were already approved. That gives AI much better continuity.

I would also establish one architectural principle at the beginning:

CarbonTally is a single multi-tenant SaaS application with role-based workspaces. Every user logs into the same application. The workspace, menus, permissions, and accessible data are determined entirely by role and organization assignments.

That one sentence will keep the AI from creating separate applications for customers, consultants, and staff.

One extra phase I strongly recommend

I would add Phase 5 – Backend API & Permissions before you start coding the UI.

That phase would define:

Every API endpoint.
Every Supabase RPC function.
Every storage bucket.
Every Row Level Security policy.
Every permission matrix.
Every role's capabilities.
Every workflow between Platform Staff, Consultants, and Organization users.

Once that's complete, your frontend AI agent can build screens against a stable backend contract instead of guessing how the application should behave. That usually leads to faster development and fewer architectural changes later.
