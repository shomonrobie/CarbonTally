## 2. CORS root cause (Parts B + C, and a **correction to DR-002**)

**Path traced** `CODE-TRACED`:

```
Browser (http://localhost:3000)
  → POST http://127.0.0.1:54430/auth/v1/token?grant_type=password
  → carbontally_demo_lab_gateway   (docker nginx:alpine, 127.0.0.1:54430→80)
       config: ~/ct_local_env/demo_lab/generated/nginx.conf (generated by tools/demo_lab/stack.py)
  → proxy_pass http://supabase_auth_carbon_ledger:9999/   (GoTrue, local stack container)
```

- Port 54430 is owned by the lab's **nginx gateway** container (`nginx:alpine`), whose config is bind-mounted read-only from the generated file above. The original generated config contained **no CORS directives at all** — three bare `location` blocks plus `location / { return 404; }`. `CODE-TRACED`
- The gateway proxies `/auth/v1/` to the local-stack **GoTrue** container (`supabase_auth_carbon_ledger:9999`; env `GOTRUE_SITE_URL=http://localhost:3000`, `GOTRUE_URI_ALLOW_LIST=https://localhost:3000`). There is no Kong: the auth container performs CORS itself. `CODE-TRACED`

**Pre-remediation preflight reproductions** `RUNTIME-OBSERVED` (`OPTIONS http://127.0.0.1:54430/auth/v1/token`, `Origin: http://localhost:3000`, `Access-Control-Request-Method: POST`):

| `Access-Control-Request-Headers` sent | Response | `Access-Control-Allow-Origin` |
| --- | --- | --- |
| *(absent)* | 204 | `*` |
| `content-type` | 204 | `*` |
| `authorization` | 204 | `*` |
| `x-client-info` | 204 | `*` |
| **`apikey`** | 204 | **absent → browser blocks** |
| **`apikey,content-type`** | 204 | **absent → browser blocks** |
| **`authorization,apikey,content-type,x-client-info`** | 204 | **absent → browser blocks** |

**Corrected root cause:** the failure is **not** "the gateway publishes no CORS allow-list" (DR-002 §§7, 9). The upstream auth service *does* answer preflights for any origin, but **its requested-headers allow-list omits `apikey`** — the header `supabase-js` always sends — so for genuine browser requests GoTrue omits `Access-Control-Allow-Origin` and the browser blocks the call. The lab nginx gateway supplied no CORS of its own, so nothing else provided the header. `BROWSER-VERIFIED` + `RUNTIME-OBSERVED`
The pre-fix response was `HTTP/1.1 204 No Content` with `Vary: Origin, Access-Control-Request-Method, Access-Control-Request-Headers` and no grant header — matching DR-002's observation, whose root-cause *attribution* is hereby corrected.

`/storage/v1/*` behaved identically (no ACAO when `apikey` present). `/rest/v1/*` already returned `Access-Control-Allow-Origin: *` (PostgREST) and therefore worked from a browser both before and after. `RUNTIME-OBSERVED`

**Intended origin (Part C):** `http://localhost:3000` — confirmed independently by `backend/config.py ALLOWED_ORIGINS` (first entry, commented "local V3 frontend (CRA dev server)"), by the auth container's `GOTRUE_SITE_URL`, and by the CRA dev server DR-002 started. No other origin is intended; no wildcard was used. `CODE-TRACED`

## 4. Exact remediation (Part D — bounded, Demo Lab only)

Changed file: **`tools/demo_lab/stack.py`** (Demo Lab tooling — not product code).

1. Added module constant `BROWSER_ORIGIN = "http://localhost:3000"`, documented as mirroring `backend/config.py ALLOWED_ORIGINS` and `GOTRUE_SITE_URL`.
2. Added helper `_cors_headers()` returning the nginx CORS directives used per location.
3. Extended the generated gateway config with:
   - an explicit `map $http_origin $lab_cors_origin` whose `default` is **empty** and whose only granted value is `http://localhost:3000` — no wildcard, no patterns;
   - gateway-served preflight (`if ($request_method = OPTIONS) { … return 204; }`) advertising `Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS`, `Access-Control-Allow-Headers: authorization, apikey, content-type, accept, x-client-info, x-supabase-api-version`, `Access-Control-Max-Age: 86400`;
   - response headers on real requests (`Access-Control-Allow-Origin`, `Access-Control-Expose-Headers`, `Vary: Origin`) for the granted origin only;
   - `proxy_hide_header Access-Control-Allow-Origin;` / `proxy_hide_header Vary;` so an upstream `*` can never surface beside the gateway's explicit grant (one coherent CORS authority, no duplicate headers);
   - applied to the two locations that actually failed — `/auth/v1/` and `/storage/v1/`. `/rest/v1/` was left untouched because it already works from a browser. `CODE-TRACED`

Deployment (Part F — minimal restart):

```
python3 -c "import sys;sys.path.insert(0,'tools/demo_lab');import stack;print(stack.ensure_containers())"
# → {'started': ['carbontally_demo_lab_gateway'],
#    'already_running': ['carbontally_demo_lab_postgrest'], …}
docker exec carbontally_demo_lab_gateway nginx -t   # syntax ok / test successful
```

The lab tooling regenerated the config and re-created **only the gateway** container; PostgREST stayed up (uptime 6 h, untouched). `RUNTIME-OBSERVED`
`LIMITATION`: the same tooling call also re-created the lab **storage** container (its `ensure_container()` is unconditional). Storage objects live on the docker **volume** `carbontally_demo_lab_storage` → `/mnt`, so objects persisted; no object was written or deleted. No database, RLS, seed, migration or product data was touched.

## 5. Security impact assessment

| Property | After the change |
| --- | --- |
| Allowed origins | **Exactly one** (`http://localhost:3000`); `map` default empty → every other origin gets **no** grant |
| Wildcard | **Not introduced.** `Origin: http://evil.example` → 204 with **no** ACAO; `Origin: http://localhost:3100` → **no** ACAO |
| Upstream wildcard leak | Prevented by `proxy_hide_header Access-Control-Allow-Origin` (browser can no longer see upstream `*`) |
| Allowed request headers | Explicit list; includes the previously rejected `apikey`; no `*` wildcard |
| Credentials mode | `Access-Control-Allow-Credentials` **not** sent; the app uses `Authorization: Bearer`, not ambient cookies |
| Authentication / authorization | Unchanged — GoTrue still issues JWTs; PostgREST and FastAPI still validate them; lab backend CORS allow-list and RLS untouched |
| RLS / storage policies / schema / migrations | **Unchanged** — no DDL/DML was executed |
| Blast radius | Lab gateway container + lab generator only; the shared auth container and the neighbouring project were not modified |

**Verdict:** no security boundary was weakened. The change converts "browser cannot authenticate" into "exactly this one explicit origin may authenticate in a browser" — CORS *correctness*, not CORS *loosening*. `RUNTIME-OBSERVED`

## 22. Final bounded verdict (item 25)
